Suggest a feature: user flows

Phase 1 is a single feedback form. Signed-in users open it from Settings in the app or from the account menu on polymarket.us. Every submission lands on a private Featurebase board with the user's account attached. There are no pop-ups and no public board. Phase 2, sketched at the bottom, adds user-facing "What's new" release notes.

Attached automatically, never shown as fields: user ID, username, platform (ios, android or web), app or web build version, the entry point (settings, account_menu or direct), locale, and timestamp. These go into the post's author and custom fields.

Bug reports stay out of this form. The footer sends people to support, so CX volume doesn't land in the product inbox. Market ideas are parked for now and still go through Discord. Screenshots, a public board, voting, and status updates sent to users are also left out of phase 1.

Phase 2, brain dump

What's new

The same pattern of a hosted page plus a native or web container can show users release notes. Each release gets one entry with a level that sets how loud it is. This is a rough sketch for discussion, not a spec.

Release record, one per release

  • id, platforms (ios, android, web), and the min_version it applies to
  • level: major is a takeover or modal, minor a card plus inbox, fixes inbox only
  • title, hero (image or video), items[] (title, body, image, deep link)
  • publish_at. Authored in Mission Control next to the version gates, or in Featurebase Changelog if we stay on their stack

Surfaces

  • polymarket.us/whats-new/[id]: one template that renders in the app sheet, the web modal and as a full page
  • App: on launch, compare the installed version with the last seen release and pick a surface by level
  • Inbox: every release creates a notification whose actionUrl points at the page. The admin UI's bulk send already supports this
  • Update gate: GET v1/integrity-check/config already returns current and min versions, set by env vars on go-gateway-us (IOS_CURRENT_VERSION, IOS_MIN_VERSION and the Android equivalents). Current gives a skippable prompt, min a blocking one, and both show the notes

Closes the loop with phase 1

  • A release item can link the Featurebase posts it addresses
  • People who suggested or upvoted it get "You asked, we shipped" in their inbox
  • Every What's new surface has a "Suggest a feature" link that opens the phase 1 form in place, and tells people the form lives in Settings and the account menu, so phase 1's quiet entry points get found without pop-ups
  • That gives users a reason to keep sending ideas, without needing a public board
