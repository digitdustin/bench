Settlement glide

Keep the chart on the live BRTI print, then, in the final 60 seconds, glide the line and the headline price onto the number that actually settles the market. At 0:00 the screen shows the settlement price exactly, and before that it shows the best estimate of it. Watch the charts first. The formula and the build notes are further down.

Every rule on this run

"Feels live" is the average 1-second move of the displayed price as a share of spot's. "Losing side" counts the seconds in the final minute where the screen showed the side that ends up losing. "Off at 0:00" is the last displayed value minus the settlement price. Green is the best on this run, red the worst.
The approach

One formula, three phases

Settlement averages the 60 one-second prints before close. Partway through that minute, some of those prints are already fixed and the rest haven't printed yet. The projection keeps the fixed ones as they are and fills each second still to come with the current price. The result is the settlement price if spot doesn't move again from here.

D(t) = ( Σ P[T−60 … t] + (T−1−t) · P(t) ) / 60
Until 1:00 left

Spot

D = P(t). The chart stays exactly as live as it was before the flag.

1:00 to 0:01 left

The glide

Each print that lands is fixed in the average. A spot move moves the screen by its share of the seconds left: all of it at 1:00, half at 0:30, a sixth at 0:10.

0:00

Settlement, exactly

All 60 prints are in, so D equals the settlement price to the cent. The display can't disagree with the result.

Every Up/Down window closes on a whole minute, so one projection per asset covers 5m, 15m, 1h and longer markets alike.

We do. CF Benchmarks only publishes the BRTI print, once per second.

Settlement is the equal-weight mean of the 60 cent-rounded prints in [T−60s, T), rounded half-up to the cent. A missing second blocks auto-settlement. Price to beat appears to be the same mean over the minute ending at window start.

Show detail
Index
CF Benchmarks BRTI. Chainlink is the international app's TWAP feed, not this one.
Samples
One print per whole second, each rounded to the cent first.
Window
[T−60s, T): the 60 prints strictly before close. This applies to instruments minted from Sep 23. Older ones use (T−60s, T].
Mean
Sum of cents ÷ 60, rounded half-up. Equal weight, nothing trimmed.
Gaps
Any spacing over 1.5s is reported. With a gap, the market goes to manual settlement (Sep 23 incident: a 59-print minute).
Price to beat
Stamped 1–3s after window start from "a mean of the same window". That reads as the minute ending at start, the previous run's settlement (inferred).
Tie
Settlement ≥ price to beat resolves Up.

Off by one second. The rolling stream averages (t−60s, t], but settlement uses [T−60s, T). So the TWAP line's last frame at 0:00 includes the print at T and drops the one at T−60, and can miss settlement by a dollar or two. That's the "Off at 0:00" column in the playground table.

In asset-price-service, as one optional message on each frame. The gateway passes it through.

The service already reads every print for the rolling stream. Add a per-asset accumulator for the current minute that tracks the sum, the count and the latest print, and emit the projection with each frame. It needs no market lookup, because the minute boundary is enough.

// gateway.asset_prices.v1, passthrough from asset-price-service
message AssetPrice {
  AssetId   asset     = 1;
  Amount    price     = 2;  // back to the raw BRTI print
  Timestamp timestamp = 3;
  SettlementMinute settlement_minute = 4;  // new
}

// The minute [minute_end − 60s, minute_end) that settles every
// window ending at minute_end (5m, 15m, 1h, 4h, 1d all do).
message SettlementMinute {
  Timestamp minute_end      = 1;
  int32     prints_observed = 2;  // k, 1…60
  Amount    observed_mean   = 3;  // mean of the k prints
  Amount    projected       = 4;  // D(t), cent, half-up
  bool      has_gap         = 5;  // settlement will go manual
}
Service: a per-asset accumulator on the print loop 
// asset-price-service, fed the same cent-rounded 1 Hz prints
// that GetWindowAverage reads.
type minuteProjector struct {
  start time.Time  // first second of the minute
  sum   int64      // cents
  n     int64
  last  time.Time
  gap   bool
}

func (m *minuteProjector) OnPrint(ts time.Time, cents int64) *SettlementMinute {
  start := ts.Truncate(time.Minute) // print at T opens the next minute
  if !start.Equal(m.start) {
    *m = minuteProjector{start: start, gap: !ts.Equal(start)}
  } else if ts.Sub(m.last) > 1500*time.Millisecond {
    m.gap = true
  }
  m.sum += cents; m.n++; m.last = ts
  left := 59 - int64(ts.Sub(start)/time.Second) // seconds still to print
  return &SettlementMinute{
    MinuteEnd:      start.Add(time.Minute),
    PrintsObserved: m.n,
    ObservedMean:   divHalfUp(m.sum, m.n),
    Projected:      divHalfUp(m.sum+left*cents, m.n+left),
    HasGap:         m.gap,
  }
}

Inside the run's final minute, the line, big price, change chip and color read projected in place of the print.

Outside the final minute nothing changes. The "60s avg" label becomes something like "Settling at, 23/60 in". A faint spot line behind it is optional. There's also a client-only shortcut, but it needs raw prints back on the wire.

// crypto-event-chart.logic.ts
export function cryptoDisplayPrice(frame: LiveAssetPrice, windowEnd: number): Usd {
  const minute = frame.settlementMinute
  // Outside this run's final minute the line is spot.
  if (!minute || minute.minuteEnd !== windowEnd) return frame.price
  return minute.projected
}

Three facts to check with the backend team, and one copy decision.

Is the settler on [T−60s, T)?

The mission-control verifier and docs say so for instruments minted since Sep 23. The settler itself is in pmx-monorepo, which we couldn't read.

Was the average the goal of the flag?

rollout_asset_price_service moves the source to asset-price-service and switches every frame to the average, in one step. Ask whether the average was intended, or came along with the migration.

How is price to beat stamped?

The 1–3s stamp latency suggests the minute before window start. The ingestor's older Redis price_to_beat path uses the last print at the boundary.

What does the UI say during the glide?

Something like "Settling at $84,341.20, 23/60 in". The tie rule (≥ resolves Up) also needs to show when the line sits on the target.
